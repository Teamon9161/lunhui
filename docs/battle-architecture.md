# 《轮回坛》战斗架构与性能要求

更新日期：2026-10-30。本文恢复早期设计中的性能方向，并结合用户本次澄清，明确 FairyGUI 与战斗运行时的边界。项目整体目标见 [项目背景与技术决策](project-context.md)。

## 要达到的结果

采用 Cocos Creator 3.8.x，做出接近 `my_zzbx` 完成度的角色动作与技能表现，同时改进其可能产生卡顿的战斗架构。手机是首要运行目标，不能以高性能 PC 流畅作为手机达标的证据。

旧整理认为原版“完整子弹实体＋刚体＋FairyGUI 节点”和 Rapier 范围查询可能带来开销；原记录没有实测性能。这里将其作为需要避免和验证的架构风险，不把它写成已证实的唯一根因。不得承诺仅更换引擎版本或移除 FairyGUI 就一定消除卡顿。

## 分层与边界

| 层 | 负责内容 | 约束 |
| --- | --- | --- |
| 纯 TypeScript 战斗核心 | AI、移动、寻敌、弹丸、范围判定、状态、伤害、波次、随机与事件 | 固定 30Hz；种子随机；不依赖 `cc`、FairyGUI、浏览器或通用物理引擎；可独立模拟与测试 |
| Cocos 战斗表现层 | 场景、角色、武器、弹丸、地面效果、技能特效、单位血条、头顶状态、伤害飘字、音效 | 根据核心状态与事件更新；组织图集/材质合批与节点/特效复用；不为每颗弹丸构建带刚体和大量组件的完整实体 |
| FairyGUI 界面层 | 菜单、养成、选项、设置、弹窗等 UI | 不参与寻敌、物理、战斗逻辑或战场物体渲染；不把单位、弹丸、特效、头顶标识包装成 GUI 组件 |

战斗页面的暂停、倍速等控制按钮若使用 FairyGUI，也仅作为独立的屏幕 UI，通过命令接口影响战斗；不得借此把整个战场接回 FairyGUI 组件树。随单位逐帧移动、数量随敌群增长的血条/飘字属于战斗表现层。

## 战斗实现原则

- **逻辑与绘制解耦。** 固定 30Hz 逻辑，目标 60Hz 绘制，移动可做渲染插值。画面插值不改变结算；攻击、出手、命中和状态结束按同一模拟时间同步，暂停和倍速也使用该时间关系。
- **网格查询。** 使用现有空间哈希进行附近单位检索、范围命中及简单碰撞处理，不为这些查询引入 Rapier 或其他通用物理世界。保留玩法语义，不以性能优化改变有效目标与命中规则。
- **轻量弹丸。** 弹丸在核心中为数组中的轻量数据；增加明确的回收/复用策略，避免密集生成销毁导致分配尖峰。碰撞、穿透、弹射等机制由核心处理，不依赖每颗弹丸上的刚体、碰撞组件或 GUI 对象。
- **复用运行时资源。** 对高频角色视图、弹丸、特效和飘字使用池或可复用缓冲。预热常用资源；战斗中避免同步加载以及密集实例化/销毁；热点临时数组、闭包和事件对象的分配结合分析结果收敛。
- **按实际条件合批。** 规划角色和效果图集、共享材质、渲染层次；避免无谓的纹理、材质和遮罩切换。图集或 Sprite 节点本身不保证合批，必须检查真实渲染批次。保留正确的前后遮挡与透明混合。
- **控制特效与 UI 成本。** 对透明大面积叠加、粒子、屏幕闪光、状态标记和伤害飘字设合理预算。可合并同帧重复飘字、复用相同状态表现，但保留关键技能、命中范围和反馈；不能把优化退化为用圆点代替正式角色动作。
- **性能问题先测量。** 区分逻辑耗时、渲染提交、GPU 填充、资源加载、GC、UI 更新和设备温度变化，不仅凭节点数或使用的框架下结论。自定义批量渲染、数据布局重写等进一步优化以实测瓶颈决定。

## 早期压测与验收

历史目标：**中端安卓机上 150 个活动单位＋400 颗活动子弹，目标稳定 60 FPS。** 这是待验证的目标，尚无真实设备通过记录；具体设备型号、分辨率和运行模式必须在结果中注明。

压测从第一批表现资源接入时开始，持续维护可复现的种子、阵容和场景配置。需要覆盖真实动作播放、代表性材质与特效、范围/状态结算、子弹持续生成与回收；不能只画 550 张静态图片或只跑无渲染模拟。

至少记录：

- 设备、系统、包版本、构建模式、分辨率、测试时长与活动对象数量。
- 平均帧率、帧耗时分布（包括 P95/P99）和长帧，避免均值掩盖卡顿。60 FPS 的整帧预算约为 16.7ms。
- 逻辑/脚本耗时、渲染批次/提交开销，以及工具可提供的 GPU 指标。
- 内存和分配/GC 情况；反复战斗、资源回收及长时间运行后的变化。
- 同屏大技能叠加、召唤/死亡/复活突发、暂停/恢复、1倍与倍速运行的结果。倍速增加模拟工作量，应单独说明。

先建立基线，遇到超预算按分析结果修复并复测。尚未接到目标设备时，可以记录 PC/模拟器数据辅助开发，但必须保留手机验收未完成的状态。画面与性能都需要真实战斗验证，不能相互替代。
