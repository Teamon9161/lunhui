# 角色动作制作：路线、要点与素材

更新日期：2026-10-30。本文汇总精卫动作样板中得到的经验，后续英雄照此制作。工具位于 `art/tools/`，Cocos 接入见 [Cocos 正式工程](cocos-client.md)，精卫的具体规格见 [art/heroes/jingwei/brief.md](../art/heroes/jingwei/brief.md)。

## 已确定的路线

用户于 2026-10-30 确认：

| 动作类型 | 做法 | 理由 |
| --- | --- | --- |
| 普攻、技能、移动、受击、阵亡等有姿态变化的动作 | **AI 逐帧条带**：一致性提示词，后处理按脸统一比例、整帧对齐（`gen.py` → `prepare_frames.py`） | 动作自然，幅度不受限；动作快，细微差别不易察觉 |
| 待机等小幅度、常驻屏幕、循环播放的动作 | **单图变形**：只用一张通过的帧，按部位遮罩、支点、摆角和相位生成各帧（`rig_frames.py`） | 所有帧来自同一份像素，头身比例和五官每帧完全一致。这类动作被盯着看的时间最长，逐帧重画最容易"胀缩" |

**已试过并放弃的路线**（不要再提）：
- **分件骨骼动画**：用户用 Google 图像模型出了唐僧分件图，助手拼装出待机和念经动作（相关图片和工具已删除）。脚和下摆接不上、念珠位置不对、像纸片人，调整耗时长、成本高，用户评价不采用。原因是 AI 画的部件不是为拼装设计的。
- **视频模型生成动作**：用户了解后认为比现有方式更麻烦，不采用。
- **3D 建模渲染**：难以还原已定稿的手绘动漫画风，不作为路线。

## 人物动作生成要点

### 提示词

每位英雄的 `art/heroes/<英雄>/prompts.md` 由 `## common` 和各动作段落组成，`gen.py` 自动拼接。精卫的 [prompts.md](../art/heroes/jingwei/prompts.md) 是完整范例。

1. **固定附参考图**：第一张是定稿形象图；待机通过后，其余条带都把待机图作为第二张参考。
2. **锁定形象**：逐项写出发型、标志物、服饰、配色、武器，写明"与参考图相同的头身比例和画风"。
3. **锁定头部**：每个动作段落都加头部一致性要求，即与待机图同样的头宽、眼睛大小、发量和脸型。精卫普攻 v1 就是缺了这段，脸画大了。
4. **版式写死**：1536×1024，3×2 宫格，每格 512；人物约 400px 高，脚踩同一条地平线（距底边约 40px）；四周留 30px 以上空白，内容不得越格；全程朝屏幕右侧、三分之四侧面，不镜像、不背身。
5. **背景**：纯绿 `#00FF00`，无渐变、地面、投影、光晕、网格、文字。
6. **按关键姿势写每一格**：按"预备 → 蓄力 → 出手 → 随势 → 收势"排列，写明哪一格是离手帧；一张图只做一个动作，最多 6 格；循环动作相邻格的变化要小。
7. **禁止项**：动态模糊、半透明、渐隐、光效、多余道具。淡出、闪白、残影、技能光效一律由代码或独立特效做。
8. **显示尺寸**：说明角色在游戏里约 150px 高，外轮廓略加粗，只省略最细碎的分格（如羽毛）。

### 出图与筛选

- `python -I art/tools/gen.py <英雄> <动作> <参考图...>` 调用 Codex 内置 image_gen，输出 `raw/<动作>-vN.png`。**先出待机**，通过后再出其他动作。
- 逐格检查：脸、服饰是否走样，有无越格、半透明、多余道具。不合格就改提示词重出，不要靠后处理硬救。
- 定稿形象或动作在用户确认前都是生产稿，生成完成不代表通过；反馈和修改记在该英雄的 `brief.md`。

### AI 逐帧的常见问题与对策

以下问题都在精卫样板中实际出现过：

| 现象（用户反馈或检查发现） | 原因 | 对策 |
| --- | --- | --- |
| 待机左右晃动生硬 | 某一帧整体横移约 4 像素；各帧细节不同 | 整帧图像相关对齐（`anchor: "align"`）、按相似度重排帧序（`order`）、循环换帧处短暂淡入（`blend`） |
| 普攻时脸变大 | 不同条带画出的头身比不同（脸更圆、眼更大、发量更多）；按身高统一比例反而放大了脸 | 提示词加头部一致性段落；以待机第 1 帧的脸为模板做多尺度匹配，按脸统一各条带比例（默认 `scaleBy: "face"`） |
| 待机时头部忽大忽小 | 测量脸的大小只差 1–2%，真正原因是每帧头发轮廓、蓬松度不同，循环时像在胀缩 | **对齐和缩放修不了"画得不一样"**。改用单图变形生成待机 |
| 掷出的石子出现在下一格 | 内容越过了宫格边界 | `dropSpill: true` 去掉贴边的小块独立部件；提示词要求每格留空 |
| 阵亡最后一帧、尘爆最后一帧不可用 | AI 把"淡出"画成半透明，与绿幕混色后无法抠干净 | 不让 AI 画半透明，淡出交给代码 |
| 倒地动作按脸缩放失败 | 脸部被遮挡或角度变化，模板匹配不可靠 | 该条带改用 `scaleBy: "height"` |

结论：逐帧生成能保证"像同一个角色"，不能保证"每帧是同一张脸"。循环、慢速、常驻画面的动作必须同源；快速、大幅度的动作可以接受逐帧。

## 工具流程

### 单图变形（`rig_frames.py`）

1. 选一张已通过的帧作为源（精卫用待机第 1 帧）。
2. 写配置 `art/heroes/<英雄>/<名称>.json`，每个部位定义：
   - `include` / `exclude`：矩形 `rect: [x0, x1, y0, y1]` 或圆 `circle: [cx, cy, r]`，`feather` 为边缘渐变宽度；坐标是 512 格内像素，y 向下；
   - `move: [dx, dy]`：呼吸最高点的位移；
   - `rotate`：一个周期内的总摆角（度），绕 `pivot` 转；
   - `lag`：相位滞后（周期比例），用于翅膀、羽冠、尾羽的跟随感。
3. `python -I art/tools/rig_frames.py <英雄> <名称>` 输出 `rig/<名称>/NN.png`，再在 `frames.json` 里以 `rgbaFrames` 引用。
4. 精卫待机的参数（`art/heroes/jingwei/idle-rig.json`）可作为起点：上身起伏 2.4px，头部轻点 1.6°，羽冠 7°，翅膀 3–3.5°，尾羽 4°；脚和腿不动。幅度过大会出现拉伸痕迹，遮罩边界附近尤其明显。

只适合小幅度动作；蹲下、转身、倒地会暴露原图中不存在的部分。

### 后处理与打包（`prepare_frames.py`）

`python -I art/tools/prepare_frames.py <英雄>` 读取 `frames.json`，依次完成：
1. 抠绿幕（含去溢色）、去杂点；
2. 统一比例、脚底贴地、水平对齐；
3. 打包图集。

输出 `frames/`（单帧，审阅用）、`preview.gif`，以及运行时的 `client/assets/resources/heroes/<英雄>/atlas.png` 和 `anims.json`。

| 键 | 作用 |
| --- | --- |
| `source` / `cells` | 原始条带与格数 |
| `rgbaFrames` | 改用已抠好的 RGBA 帧目录（单图变形的输出） |
| `use` | 只取其中几格 |
| `ref` | 对齐与比例的基准格 |
| `dropSpill` | 去掉贴边的越格内容 |
| `scale` / `scaleBy` / `refHeight` | 固定缩放 / 按 `face`（默认）或 `height` 统一 / 指定基准身高 |
| `anchor` | 水平对齐方式：`cell`、`head`（跑动时稳住头部）、`center`（特效）、`align`（整帧图像相关） |
| `order` | 播放帧序 |
| `loop` / `hold` | 循环 / 停在最后一帧 |
| `durations` / `blend` | 每帧时长 / 循环换帧淡入 |
| `release` / `pre` / `post` | 离手帧序号，以及前摇段、收势段各帧的时长占比 |
| `muzzle` | 离手帧中弹丸出手点：相对脚底的设计像素，x 沿朝向，y 向上 |

顶层的 `face` 指定比例模板（哪张条带的哪一格），`targetHeight` 是打包后的站立高度，`pixelsPerUnit` 是图集像素与设计像素之比。名称以 `fx_` 开头的动作视为特效，不做脸部缩放，提示词也不拼接 `common`。

### 与战斗核心对齐时序

- 英雄定义里配置 `timing: { attack: [前摇, 收势], cast: [...] }`。核心在动作开始时发 `act` 事件，**前摇结束那一刻才结算**（生成弹丸、造成伤害）；前摇中被眩晕则发 `actCancel`。攻速同比缩短前摇和收势。
- 表现层按 `pre` 占比把离手帧之前的帧拉伸到恰好等于前摇，按 `post` 分配收势段，因此离手帧与弹丸生成在同一逻辑步。
- 弹丸视觉上从 `muzzle` 点飞出，0.15s 内并入核心弹道，结算不受影响。
- `bun client/tools/showcase-trace.ts` 打印出手时刻与弹丸时刻，可用于核对。

## 交付前检查清单

1. 按实际游戏尺寸（站立约 130 设计像素）看动作预览（`?mode=preview`），不只看大图。
2. 循环动作至少看三个循环，注意头部、头发、翅膀有无胀缩或跳动。
3. 逐个条带对比脸的大小和形状，与待机第 1 帧放在一起看。
4. 用 `showcase-trace.ts` 或战斗录屏确认离手帧与弹丸同帧。
5. 在压测模式核对批次（每位英雄一张图集，战场应保持个位数批次）。
6. 交给用户试玩确认，反馈记入该英雄的 `brief.md`。

## 其他已知坑

- 精灵颜色只能相乘变暗，受击白闪需要专用材质，目前用偏红色调代替。
- 动作之间的切换用叠加精灵淡入，不要直接硬切。
- Codex `exec` 的提示词要通过标准输入 `-` 传入，参考图用 `--image=<绝对路径>`；`-i` 会吞掉提示词。

## 素材入库规则

仓库只保存**最终采用的素材**和重新生成运行时资源所需的源文件：
- 形象定稿图与参考图；
- 正在使用的动作条带原图（`raw/` 中被 `frames.json` 引用的版本）；
- 各配置文件；
- `client/assets/resources/` 下的运行时图集。

被淘汰的版本、Codex 日志（`.out`）、可由脚本重新生成的中间产物（`frames/`、`rig/`、预览 GIF），以及历史探索图，只留在本地，由根目录 `.gitignore` 排除。新增素材时同步维护 `.gitignore`。
